## 一、AI 生成能力优化

### 1. PPT 生成耗时优化（AI 工作流耗时）

### 2. PPT 生成知识上传增强

**待修改或添加的功能**：发起生成时可临时上传参考资料，增强本次生成的专业性，而不必先入素材库。

**具体实现方案**：

- 前端生成入口增加「临时上传」通道（支持与素材库同时勾选）；
- Python 端：临时文件解析 → 向量化 → 仅注入本次大纲/页面生成的检索上下文；
- 会话结束自动清理临时索引，同时提供「一键转存个人素材库」按钮复用现有 OSS 上传链路。

### 3. 教师风格系统接入

**待修改或添加的功能**：让生成结果贴合教师个人教学风格，减少反复修改。

**具体实现方案**：
- **画像采集**：从教师历史教案/PPT、生成采纳率、修改记录中提取风格特征（结构偏好、语言风格、配色版式、详略程度），定期任务更新（PostgreSQL 已规划教师风格画像存储）；
- **画像注入**：大纲工作流与 PPT/教案生成 prompt 中拼接风格画像描述；
- **前端入口**：账户设置增加「我的教风」卡片，支持查看/编辑风格标签、风格跟随开关、从历史作品重新学习。

### 4. 各学科教学方式区分

**待修改或添加的功能**：不同学科采用不同教学方式与页面结构，避免"千课一面"。

**具体实现方案**：
- Java 端建立学科配置表（学科 → 教学法模板、页面结构模板、示例库）；
- 生成入口增加学科/课程属性选择，大纲工作流按学科路由不同 prompt 模板（理工：推导/实验演示；文科：案例研讨；外语：情境对话等）；
- 管理端可维护学科模板库与示例。

## 二、教学设计能力扩展

### 5. 教学模型融入（BOPPPS 等）

**待修改或添加的功能**：教案与课件生成支持按标准教学模型组织结构。

**具体实现方案**：
- 教案/PPT 生成时支持选择教学模型（首期 BOPPPS：导入 Bridge-in、目标 Objective、前测 Pre-assessment、参与式学习 Participatory Learning、后测 Post-assessment、总结 Summary）；
- Python 端教案生成器增加 BOPPPS 结构化模板，按六段式生成教案段落与对应页面；
- 大纲工作流按所选教学模型重组章节结构，大纲确认页展示模型映射关系。

### 6. 思政教育与时政融合

**待修改或添加的功能**：生成内容自动融入思政元素与时政素材，响应课程思政要求。

**具体实现方案**：
- 公共知识库增设「思政案例库」「时政素材库」分区，管理端维护并定期更新时政热点；
- 大纲/教案/PPT 生成时按学科自动检索思政/时政素材（复用 RAG 检索），在 prompt 中给出融合建议；
- 生成结果中标注引用的思政/时政素材来源，教师可一键移除或替换。

### 7. 学科组件（公式组件等）

**待修改或添加的功能**：课件页面支持公式、化学方程式、图表等学科专用组件。

**具体实现方案**：
- 扩展页面模板库组件集：数学公式（LaTeX + KaTeX/MathJax 渲染）、化学方程式、函数图像/坐标系、流程图（mermaid）、数据图表（echarts）；
- Python 端生成器在页面 JSON 中输出公式 DSL，前端预览时渲染；
- PPTX 导出时公式转换为图片或 OMML，保证离线可用。

### 8. 组织试卷能力

**待修改或添加的功能**：平台可按知识点/题型/难度自动组卷。

**具体实现方案**：
- Python 端新增试卷生成工作流：输入（学科、知识点、题型、难度分布、题量）→ 双向细目表确认 → 逐题生成 → 组卷校验；
- 题型支持：选择/填空/判断/简答/计算（计算题结合公式组件）；
- 前端工作台新增「试卷」创建入口与在线预览编辑；
- 复用导出中心链路，新增试卷 DOCX/PDF 导出（学生卷 + 答案卷双版本）。

## 三、课堂互动

### 10. 为学生服务，增加课程互动

**待修改或添加的功能**：现有互动模块（练习/测验 HTML）从"嵌在课件里"扩展为"学生可直接参与"。

**具体实现方案**：

- 互动模块生成后产出分享短链/二维码，学生手机扫码参与（需免登录或轻量身份标识）；
- 新增实时互动题型：投票、抢答、随机点名；
- 教师端大屏实时展示答题统计（正确率分布、选项占比）；
- 技术：短链服务（Java）、答题回传接口、实时统计（WebSocket 或轮询降级）。

## 四、社区与资源复用

### 11. 社区优质内容快速发现（点赞/收藏排序/热门榜单）

**待修改或添加的功能**：教师按主题找同类 PPT 时能快速找到最好的作品。

**具体实现方案**：

- **点赞**：新增点赞表（user_id + target 唯一索引防重），作品详情与列表展示点赞数；
- **排序**：社区列表增加排序维度（点赞数/收藏数/复用数 × 时间段：日/周/月/总）；
- **热门榜单**：Redis ZSET + 定时聚合任务，社区首页展示「本周热门 PPT/教案/互动模块」榜单；
- 榜单入选前置条件：审核通过 + 互动数据达标，防刷量（点赞频率限制，复用 Redis 限流）。

### 12. 社区复用展示强化（前端）

**待修改或添加的功能**：强化社区复用闭环的展示与激励。

**具体实现方案**：
- 作品详情页展示复用数据（被复用次数、衍生作品列表）；
- 「一键复用到工作台」：将社区作品复制为我的项目草稿，保留溯源标记（原作者、原作品链接）；
- 复用产生的新作品投稿后展示「基于 XX 作品复用」链路，形成原创激励。

### 13. AI 检索社区素材 / 公共资源库素材

**待修改或添加的功能**：生成工作流的检索范围从个人素材库扩展到社区优质作品与公共资源库。

**具体实现方案**：
- 将审核通过的社区作品（PPT/教案/互动模块）与公共资源库纳入 Python 端 pgvector 索引（复用现有索引异步同步机制，新增来源分区）；
- 生成入口提供检索范围勾选：个人素材库 / 社区作品 / 公共资源库；
- 检索命中内容引用时标注来源与作者，教师可一键跳转原作品（为复用引流）。

### 14. 项目自维护公共知识库

**待修改或添加的功能**：把公共知识库做成运营级能力，持续产出高质量共享知识。

**具体实现方案**：
- 在管理端现有公共资源/知识库管理基础上，补充：知识条目结构化（学科/主题/标签体系）、批量导入（Excel/ZIP）、版本管理与回滚；
- Python 端为公共知识库建立独立索引分区，支持定时全量重建 + 增量同步任务；
- 增加使用统计看板（素材被引用次数、引用后生成质量反馈），指导内容运营。

## 五、平台治理与基础设施

### 15. 审核 + AI

**待修改或添加的功能**：社区投稿人工审核前增加 AI 预审，降低审核人力成本。

**具体实现方案**：
- 投稿提交后先经 LLM 预审：政治敏感、广告导流、侵权嫌疑、内容质量分；
- 审核列表增加「AI 建议」列（建议通过/建议驳回 + 判定依据），人工最终裁决；
- 高分 + 低风险内容进入"快速通道"（自动通过候选，仍抽检），低分直接拦截；
- AI 判定依据随审核记录留存，可追溯。

### 16. Agent 自更新

**待修改或添加的功能**：AI 能力（prompt/模板/知识）无需发版即可更新迭代。

**具体实现方案**：
- **Prompt/模板热更新**：将工作流 prompt、页面模板从代码抽离存 DB（管理端 AI 参数配置已有基础），Python 服务监听变更或定时拉取，修改即生效无需重启；
- **知识自更新**：公共知识库定时任务自动抓取/更新时政与学科素材；
- **质量数据回流**：导出质量报告、用户修改 diff 聚合分析，生成优化建议供人工确认后更新 prompt（不做全自动变更，保留人工审核闸门）。

### 17. 移动端界面

**待修改或添加的功能**：完善 frontend-app（Capacitor）的移动端体验。

**具体实现方案**：
- 移动端定位为「查看 + 轻交互」：工作台对话（含语音）、项目/素材浏览、社区浏览与收藏、导出任务查看与下载；
- 生成类重交互（PPT 编辑器、教案编辑器）保留在 Web 端，移动端引导跳转；
- API 继续以 `VITE_API_BASE` 直连网关，注意 SSE 在原生壳内的兼容（降级轮询）与文件下载的本地保存（Capacitor Filesystem）。

### 18. 上课素材一键获取与生图模型接入

**待修改或添加的功能**：解决教师"上课素材"痛点——文字素材检索一键获取、图片素材 AI 生成。

**具体实现方案**：
- **素材一键引用**：在大纲/页面生成工作流中直接呈现检索结果（个人库/社区/公共库），点击即引用到当前章节；
- **生图模型接入**：Python 端新增 OpenAI 兼容的图像生成接口（文生图/图生图），页面生成时可按页面内容自动配图或由教师指定生成，产物统一存 OSS 并入素材库；
- 管理端 AI 参数配置中增加生图模型选择与用量限额。

## 六、知识图谱驱动的教与学

> 落地思路：以「双图谱」为结构化底座 → 图谱驱动内容生成（PPT/视频）→ 剪枝控制成本 → 学情数据回流图谱，形成「教学生成」与「学情分析」双向闭环。

### 19. 课程知识图谱与技能图谱构建

**待修改或添加的功能**：为每门课程沉淀「知识图谱（知识点及其关系）+ 技能图谱（能力要求）」双图谱集合，作为内容生成与学情分析的结构化底座。

**具体实现方案**：

- **数据模型**：知识点节点（名称、学科、难度、Bloom 认知层级、关联素材引用）+ 关系边（先修 prerequisite / 包含 part-of / 相关 related）+ 技能节点（技能描述、掌握标准），双图谱通过「知识点 ↔ 技能」映射表关联成集合；
- **存储选型**：直接在 PostgreSQL 新增图谱 Schema（节点表 + 边表，递归 CTE 实现子图查询与拓扑排序），与现有 pgvector 同库、零新增运维成本；数据量增长后再评估 Apache AGE 图扩展，不引入 Neo4j；
- **图谱构建流水线**：Python 端新增 LangGraph 抽取工作流，从课程大纲/教材目录/已生成课件中抽取候选知识点与关系，教师确认后入图；管理端可维护学科通用图谱模板（与功能 4 学科配置协同复用）；
- **前端图谱编辑器**：工作台新增「课程图谱」页，用 AntV G6 / Cytoscape.js 可视化编辑（增删节点与连线、标注难度、拖拽调整学习顺序）；
- **与现有工作流融合**：大纲确认页增加「同步生成课程图谱」动作，大纲章节自动映射为图谱节点，教师无需重复录入。

### 20. 基于图谱生成学习 PPT 与视频

**待修改或添加的功能**：以图谱学习路径为骨架，生成覆盖知识点序列的学习 PPT（现有能力延伸）与学习视频（新能力）。

**具体实现方案**：
- **学习路径规划**：教师选定起点/目标知识点（或考试范围）后，按先修关系拓扑排序产出学习路径，支持手工增删调整节点；
- **PPT 按路径生成**：沿学习路径逐节点调用现有 PPT 生成管线，prompt 中注入该节点上下文（先修知识摘要、技能要求、关联素材检索结果），使章节衔接符合认知规律；
- **视频生成管线**（Python 端新增）：学习 PPT 的 HTML 页面 → headless 浏览器逐页渲染帧 → TTS 按页面讲稿生成旁白音频 → ffmpeg 合成 MP4；产物上传 OSS，复用导出中心的任务/预检/限时下载链路；
- **应用场景**：补弱视频（针对薄弱知识点子图定向生成）、课前预习视频（按下次课路径生成）、复习串讲视频（整门课主干路径）。

### 21. 图谱检索剪枝与模型成本优化

**待修改或添加的功能**：以「剪枝」控制大模型调用与训练代价，保证图谱规模增长不带来成本线性上涨。

**具体实现方案**：
- **检索子图剪枝**：生成/检索时从主题节点出发做 K 层邻域扩展（默认先修链 + 1 层相关节点），仅将剪枝后的子图与对应素材摘要注入 prompt，与功能 13 的检索来源勾选联动，避免全图注入导致的 token 膨胀；
- **生成范围剪枝**：教师圈定重点/考试范围时，图谱按权重（难度 × 考频）剪枝，只生成高频考点子图对应内容，同步缩短生成时间（与功能 1 耗时优化协同）；
- **训练/微调降本**（远期）：若学科/教师风格走 LoRA 微调路线，训练语料先按图谱相关性剪枝去噪再构建指令集；推理侧配合 KV Cache、请求批处理、fast/balanced/max 模型分级复用；
- **收益度量**：管理端看板展示剪枝前后 token 消耗、生成耗时、质量评分对比，用数据验证「剪枝不伤质量」。

### 22. 学生学情反馈与教师端图谱可视化

**待修改或添加的功能**：学生的学习情况（答题/练习数据）回流到教师端，映射到课程图谱形成掌握度热力图，指导后续教学与内容生成。

**具体实现方案**：
- **知识点打标**：互动模块（功能 10）与试卷题目（功能 8）在生成时自动绑定 1~N 个图谱知识点标签，作为学情数据的关联主键；
- **掌握度计算**：Python 端定时任务按节点聚合正确率，结合题目难度与 Bloom 层级加权得出节点掌握度（0~1），并沿先修边平滑传播（子节点薄弱 → 父节点预警）；
- **教师端图谱可视化**：工作台图谱页新增「学情视图」，节点按掌握度红/黄/绿着色，支持钻取（节点 → 班级错误率 → 典型错题与学生名单）；
- **以学定教闭环**：教师框选薄弱子图，一键生成补强课件/练习/视频（复用功能 20 的路径生成），实现「学情反馈 → 图谱定位 → 精准补教」完整闭环。

## 附：教师痛点背景（需求来源参考）

> 来自原始文档对教师痛点的梳理，上述功能均服务于以下痛点的解决：

- 教学设计（对应：教学模型、学科区分、思政融合）
